**V2.5.** Zwischen rohem Text und Patientenakte steht diese Schicht. Sie ist die
Stelle, an der "keine medizinische KI" durchgesetzt wird — **`extraction`
schreibt niemals Domänendaten**, sie erzeugt Vorschläge.

## Tabelle (Teil von `000027`)

    CREATE TABLE extraction_candidates (
      id           uuid PRIMARY KEY,
      household_id uuid NOT NULL,
      job_id       uuid NOT NULL REFERENCES ocr_jobs(id) ON DELETE CASCADE,
      field        text NOT NULL,      -- 'praxis','datum','gesamt','tier',
                                       -- 'diagnose','medikament','position'
      value        text NOT NULL CHECK (length(value) <= 2000),
      confidence   numeric(4,3) NOT NULL CHECK (confidence BETWEEN 0 AND 1),
      source_line  int,
      ordinal      int NOT NULL DEFAULT 0,   -- für Positionslisten
      state        text NOT NULL DEFAULT 'offen'
                   CHECK (state IN ('offen','bestaetigt','korrigiert','verworfen')),
      corrected_to text NOT NULL DEFAULT '' CHECK (length(corrected_to) <= 2000)
    );

`corrected_to` neben `value` statt an seiner Stelle: was die Engine gelesen hat
und was stimmt, sind zwei Angaben. Nur so lässt sich später beantworten, wie gut
die Erkennung wirklich war — genau die Messung, die in ADR 0009 noch aussteht.

## Parser

Regelbasiert, deterministisch, testbar. **Keine Modelle, kein Lernen.**
Grundlage sind die echten Belege aus `~/ocr-proben`, deren Text aus dem
Benchmark vorliegt.

Belegbare Muster aus diesen Dokumenten:

    Rechnungsdatum : 12.08.2026
    12.08.2026 Patient: Katze (Mischling) Mila (Geb:03.04.2021) (Chip: 2760…)
    Summe Brutto | 112,40 €
    Summe des Besuches: 94,45 €
    Beschreibung Menge Einzelpreis Gesamtpreis USt %

Die Patientenzeile liefert in einem Rutsch Tierart, Rasse, Name, Geburtsdatum
und Chipnummer. Die Chipnummer ist der zuverlässigste Anker für die
Tierzuordnung — sie ist 15-stellig und unverwechselbar, während "Nala" im
Benchmark als "Naia" gelesen wurde.

## Confidence, ehrlich gerechnet

Tesseract liefert Wort-Confidence über `tesseract ... tsv`. Die Feld-Confidence
ist das Minimum über die beteiligten Wörter, **nicht** der Mittelwert: ein Feld
ist so verlässlich wie sein schwächstes Zeichen. Ein Mittelwert würde
`13.08.2028` mit einer hohen Zahl schmücken, weil "13.08.20" gut gelesen wurde.

Drei Klassen für die Anzeige: **hoch ≥ 0,90 · mittel 0,70–0,89 · niedrig
< 0,70.** Die Schwellen gehören in `contracts.md` 2.2, weil sie die Oberfläche
steuern.

Zusätzliche Abwertung durch Plausibilität, unabhängig von der Engine:

- Datum in der Zukunft oder mehr als zehn Jahre zurück → niedrig;
- Betrag ohne Dezimaltrennzeichen oder über 10.000 € → niedrig;
- Tiername, der zu keinem Tier des Haushalts passt → niedrig;
- Praxis ohne Treffer in `vets.Match` → mittel, nie hoch.

Der Benchmark zeigt, warum das nötig ist: **eine Jahreszahl kam als 2028 statt
2026 heraus, eine andere als 2025.** Beide sahen im Text plausibel aus. Die
Engine-Confidence allein hätte sie durchgewinkt.

## Grenze

Diagnosen, Behandlungen und Medikamente werden als Kandidaten **erkannt**, nie
gedeutet. Erlaubt: "Auf der Rechnung wurde 'Metacam' erkannt." Nicht erlaubt:
irgendeine Aussage darüber, ob das Tier es bekommen soll. Kein Abgleich gegen
eine Wirkstoffdatenbank, keine Dosisableitung, keine Laborinterpretation.

## Abnahme

- `make ci`, Testdaten sind die echten Benchmark-Texte unter `testdata/`;
- Test je Feld gegen alle zehn Dokumente, mit den bekannten Fehlern als
  ausdrücklichen Fällen (2028 statt 2026, "Naia", `56.19` mit Punkt);
- Test: ein Kandidat mit niedriger Confidence wird nie automatisch bestätigt;
- Test: der Parser schreibt in keine Domänentabelle — geprüft, indem der Test
  ihm eine Datenbank ohne Schreibrechte darauf gibt;
- Schwellen in `contracts.md` 2.2.
