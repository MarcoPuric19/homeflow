**V2.5.** Die Queue liegt in PostgreSQL. Kein Broker, keine zweite
Infrastruktur — bei einem Job zur Zeit auf einem Laptop wäre alles andere
Zeremonie.

## Migration `000027_ocr_jobs` (reserviert)

    CREATE TABLE ocr_jobs (
      id            uuid PRIMARY KEY,
      household_id  uuid NOT NULL REFERENCES households(id) ON DELETE CASCADE,
      document_id   uuid NOT NULL,
      status        text NOT NULL DEFAULT 'hochgeladen' CHECK (status IN
                      ('hochgeladen','verarbeitung','pruefung_noetig',
                       'bestaetigt','fehlgeschlagen')),
      attempts      int  NOT NULL DEFAULT 0,
      available_at  timestamptz NOT NULL DEFAULT now(),
      claimed_at    timestamptz,
      claimed_by    text NOT NULL DEFAULT '',
      last_error    text NOT NULL DEFAULT '' CHECK (length(last_error) <= 2000),
      created_at    timestamptz NOT NULL DEFAULT now(),
      updated_at    timestamptz NOT NULL DEFAULT now(),
      -- Ein Dokument, ein offener Job. Das ist die Idempotenz des Uploads.
      UNIQUE (household_id, document_id)
    );
    CREATE INDEX ocr_jobs_queue_idx ON ocr_jobs(status, available_at)
      WHERE status IN ('hochgeladen','verarbeitung');

    CREATE TABLE ocr_results (
      job_id       uuid PRIMARY KEY REFERENCES ocr_jobs(id) ON DELETE CASCADE,
      household_id uuid NOT NULL,
      engine       text NOT NULL,          -- 'tesseract'
      engine_version text NOT NULL,        -- '5.5.0'
      parameters   text NOT NULL,          -- '-l deu --psm 4, 300dpi grau'
      raw_text     text NOT NULL,
      pages        int  NOT NULL,
      duration_ms  int  NOT NULL,
      created_at   timestamptz NOT NULL DEFAULT now()
    );

`engine`, `engine_version` und `parameters` sind nicht Zierde: wenn in einem
halben Jahr die Qualität anders aussieht, ist die erste Frage, womit ein
Ergebnis entstanden ist. Ohne diese drei Spalten ist sie unbeantwortbar.

`raw_text` ist Beweismittel und bleibt. Die abgeleiteten Kandidaten (HF-0125)
sind wegwerfbar und lassen sich mit einem besseren Parser neu erzeugen, ohne
das Original anzufassen.

## Ziehen

    SELECT * FROM ocr_jobs
     WHERE status = 'hochgeladen' AND available_at <= now()
     ORDER BY created_at
     FOR UPDATE SKIP LOCKED LIMIT 1

`SKIP LOCKED` auch bei einem Worker: es kostet nichts und macht einen zweiten
Worker später zu einer Konfigurationsfrage statt zu einem Umbau.

Sichtbarkeitsfrist: ein Job in `verarbeitung`, dessen `claimed_at` älter als
zehn Minuten ist, gilt als verwaist und wird wieder freigegeben. Ein Worker, der
mitten im Job stirbt, blockiert sonst dauerhaft — und mit einem Job zur Zeit
steht dann die ganze Verarbeitung.

Nach drei Versuchen `fehlgeschlagen` mit Grund. **Kein stilles Liegenbleiben.**
`fehlgeschlagen` ist keine Sackgasse: Dokument und Datei bleiben, alles ist von
Hand erfassbar. Das ist Anforderung, nicht Notausgang.
