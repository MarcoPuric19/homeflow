**V2.1.** Heute steht der Tierarzt als Freitext in `medical_records.veterinarian`
(max. 200 Zeichen). Damit ist "dieselbe Praxis wie letztes Mal" nicht
beantwortbar, und die Belegerkennung hat nichts, wogegen sie einen erkannten
Praxisnamen halten könnte.

## Migration `000022_veterinarians`

    CREATE TABLE veterinarians (
      id           uuid PRIMARY KEY,
      household_id uuid NOT NULL REFERENCES households(id) ON DELETE CASCADE,
      practice     text NOT NULL CHECK (length(practice) BETWEEN 1 AND 200),
      vet_name     text NOT NULL DEFAULT '' CHECK (length(vet_name) <= 200),
      street       text NOT NULL DEFAULT '' CHECK (length(street) <= 200),
      postal_code  text NOT NULL DEFAULT '' CHECK (length(postal_code) <= 20),
      city         text NOT NULL DEFAULT '' CHECK (length(city) <= 120),
      phone        text NOT NULL DEFAULT '' CHECK (length(phone) <= 60),
      email        text NOT NULL DEFAULT '' CHECK (length(email) <= 200),
      notes        text NOT NULL DEFAULT '' CHECK (length(notes) <= 2000),
      created_by   uuid NOT NULL REFERENCES users(id),
      created_at   timestamptz NOT NULL DEFAULT now(),
      updated_at   timestamptz NOT NULL DEFAULT now(),
      UNIQUE (household_id, practice, postal_code)
    );

    -- Optionaler behandelnder Tierarzt am Tier, fürs Vorbelegen.
    ALTER TABLE pets ADD COLUMN primary_vet_id uuid,
      ADD CONSTRAINT pets_primary_vet_fk
        FOREIGN KEY (household_id, primary_vet_id)
        REFERENCES veterinarians(household_id, id) ON DELETE SET NULL;
    -- dafür braucht veterinarians zusätzlich UNIQUE (household_id, id)

`medical_records.veterinarian` bleibt als Freitext **erhalten**. Es zu
migrieren hieße, aus Zeichenketten Entitäten zu raten. Neue Einträge bekommen
eine Referenz, alte behalten ihren Text, und die Timeline zeigt was da ist.

## Zuordnungslogik für die spätere Erkennung

Eine Funktion `vets.Match(household, practice, postalCode)` liefert
Kandidaten, **keine Entscheidung**:

- exakte Übereinstimmung auf `(practice, postal_code)` → ein Kandidat;
- normalisierter Vergleich (Kleinschreibung, Umlaute, Rechtsformen wie
  "Tierarztpraxis", "Dipl. vet. med." entfernt) → Kandidaten mit Ähnlichkeit;
- nichts gefunden → leere Liste, und der Aufrufer bietet "neu anlegen" an.

Der Benchmark aus HF-0074 zeigt, warum das nicht automatisch entscheiden darf:
derselbe Praxisname kam als `TIERZENTRUM AM SCHMELZBACH` und als
`ENBEL-E6- axisfür Kleintiermedizin` aus zwei Läufen desselben Dokuments.

ein zweites erfinden.
