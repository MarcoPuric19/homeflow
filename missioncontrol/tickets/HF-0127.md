**V2.6.** Nach `docs/product/workflows/receipt-to-insurance.md`: eine Frage, ein
Tipp, und der Fall steht — der Benutzer gibt nichts erneut ein.

**Anbieterneutral.** Kein Anbietername im Schema, keine Sonderlogik für eine
Versicherung. ADR 0005 hat Alexa und Ring aus einem verwandten Grund
ausgeschlossen; hier gilt dasselbe Prinzip in der Domäne.

## Migration `000028_insurance` (reserviert)

    CREATE TABLE pet_insurance_policies (
      id           uuid PRIMARY KEY,
      household_id uuid NOT NULL REFERENCES households(id) ON DELETE CASCADE,
      pet_id       uuid NOT NULL,
      provider     text NOT NULL CHECK (length(provider) BETWEEN 1 AND 200),
      policy_number text NOT NULL DEFAULT '' CHECK (length(policy_number) <= 100),
      coverage     text NOT NULL DEFAULT '' CHECK (length(coverage) <= 2000),
      deductible_cents bigint NOT NULL DEFAULT 0 CHECK (deductible_cents >= 0),
      reimbursement_percent int CHECK (reimbursement_percent BETWEEN 0 AND 100),
      valid_from   date NOT NULL,
      valid_until  date,
      CHECK (valid_until IS NULL OR valid_until >= valid_from),
      FOREIGN KEY (household_id, pet_id) REFERENCES pets(household_id, id) ON DELETE CASCADE,
      UNIQUE (household_id, id)
    );

    CREATE TABLE insurance_claims (
      id           uuid PRIMARY KEY,
      household_id uuid NOT NULL,
      pet_id       uuid NOT NULL,
      policy_id    uuid NOT NULL,
      encounter_id uuid,
      invoice_cents  bigint NOT NULL CHECK (invoice_cents >= 0),
      claimed_cents  bigint NOT NULL CHECK (claimed_cents >= 0),
      status       text NOT NULL DEFAULT 'nicht_eingereicht' CHECK (status IN
                     ('nicht_eingereicht','bereit','eingereicht','in_pruefung',
                      'teilweise_erstattet','erstattet','abgelehnt')),
      rejected_reason text NOT NULL DEFAULT '' CHECK (length(rejected_reason) <= 2000),
      submitted_on date, decided_on date,
      -- Ein Besuch unter einer Police ist ein Fall. Das ist die Idempotenz
      -- aus dem Workflow-Dokument, im Schema statt im Code.
      UNIQUE (household_id, encounter_id, policy_id)
    );

    CREATE TABLE insurance_reimbursements (
      id           uuid PRIMARY KEY,
      household_id uuid NOT NULL,
      claim_id     uuid NOT NULL REFERENCES insurance_claims(id) ON DELETE CASCADE,
      amount_cents bigint NOT NULL CHECK (amount_cents > 0),
      received_on  date NOT NULL,
      note         text NOT NULL DEFAULT '' CHECK (length(note) <= 2000)
    );

Erstattungen sind **eigene Zeilen**, kein Feld am Fall. Teilzahlungen sind der
Normalfall, und ein überschriebener Betrag verliert die Geschichte.

Alle Beträge in ganzzahligen Minorunits, wie überall sonst (`contracts.md`).

## Status wird abgeleitet, nicht getippt

`teilweise_erstattet` und `erstattet` ergeben sich aus der Summe der
Erstattungen gegen `claimed_cents`. Von Hand gesetzt werden nur
`bereit`, `eingereicht`, `in_pruefung` und `abgelehnt` — die Zustände, die
außerhalb des Systems passieren.

## Ablauf

Nach bestätigtem Beleg (HF-0126) prüft der Dienst, ob am Leistungsdatum eine
Police gilt. Wenn ja: **eine** Frage. Wenn nein: keine Frage, keine Erklärung.
Eine abgelaufene Police erzeugt keinen Fall, sondern einen Hinweis, dass sie an
dem Tag nicht galt.

das braucht Marcos ausdrückliche Zustimmung.
